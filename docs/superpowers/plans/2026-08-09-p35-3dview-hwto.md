## 仕様で確認済みの事実（推測しないこと）

すべて `pdftotext -layout` による実測。出典を各行に付す。

### CN4 ピンアサイン（HP-5139J p21）

| ピン | 信号 | ピン | 信号 |
|---|---|---|---|
| 1/2 | OUT0+ / OUT0−（既定 COMM-PWR） | 15 | IN-COM |
| 3/4 | OUT1+ / OUT1−（既定 ALM-B） | 16-19 | IN0-IN3（既定 ID-SEL0 / ID-SEL1 / STOP / FREE） |
| 5/6/7 | CAN_L / CAN_H / CAN_GND | 20/21 | NET-VIN / NET-GND |
| 8/9/10 | 485GND / TR+ / TR− | 22/23/24 | 485GND / TR+ / TR− |
| **11/12** | **HWTO1+ / HWTO1−** | 25 | +V（内部接続用） |
| 13 | 0V（内部接続用） | **26/27** | **HWTO2+ / HWTO2−** |
| 14 | EDM− | 28 | EDM+ |

- 入力は全てフォトカプラ。HWTO 入力電圧は DC12-30V。
- 動力遮断機能を使わないときは付属ジャンパー線で短絡しておく仕様（p21 注記）。
- 実機（図面 08015VA-24M-AA-00）は **安全リレーが HWTO1（11/12）だけを駆動し、
  HWTO2 は 25(+V)-26 / 27-13(0V) の標準ジャンパで常時 ON** という片系配線。
  図面上の `BRK-P8/BRK-N8` はハーネス側のネット名であり、CN4 の信号名ではない。

### HWTO の挙動（HP-5141J 4 章 p204-212）

- **HWTO1 OFF = インバータ上アーム駆動信号を遮断 / HWTO2 OFF = 下アーム駆動信号を遮断。**
- **両方 OFF** を検出すると「動力遮断+ETO 状態」へ移行。モーターは無励磁、SON-MON 出力 OFF、
  ETO-MON 出力 ON、電磁ブレーキ付モーターは**電磁ブレーキが保持**される、PWR/SYS LED 白点滅。
- 両方 ON で「ETO 状態」へ移行し、ETO-CLR 入力（CANopen では `40D0h` Clear ETO）で解除。
- 自己診断用オフショットパルスは **1ms 以下なら動力遮断機能は動作しない**。
- OFF 時間が 15ms 未満だと動力遮断状態へ移行できない場合がある。ON 時間が 15ms 未満だと解除
  できない場合がある（→ 本シミュレータでは 1ms 粒度で判定し、この「場合がある」は再現しない）。
- EDM-MON 出力: HWTO1/HWTO2 が **両方 OFF のときだけ ON**。他の 3 通りは OFF。
- HWTOIN-MON 出力: **どちらか一方でも OFF なら ON**。
- アラーム `53h` HWTO 入力回路異常（解除不可・無励磁）/ `68h` HWTO 入力検出（無励磁）。
- パラメータ（**MEXE02 専用。CANopen EDS には存在せず SDO からは触れない**）:
  - 「HWTO 入力 OFF 時アラーム発生」 0:無効（初期値） / 1:有効
  - 「HWTO-2 重系異常検出遅延時間」 0-10:無効（初期値 0） / 11-100 ms。
    片方の HWTO が OFF になってから、もう片方が OFF になるまでこの閾値を過ぎると `53h` 発生。

### ユーザーからの実機情報

- 安全リレーが切れたときの停止は**フリーラン（無励磁）**。電磁ブレーキが作動する音がする。

## Task 4: `HwtoModel`（driver 層）

**Files:** Create `omsim/driver/hwto.py` / Test `tests/unit/test_hwto.py`

**Interfaces:**
- `HwtoModel(alarm_on_off_input=False, dual_mismatch_delay_ms=0)`
- `.set_inputs(hwto1_on, hwto2_on, dt)` — 1ms ごとに呼ぶ
- `.power_cut` — どちらか OFF（= 該当アーム遮断 → トルクを出せない）
- `.eto_active` — 両方 OFF を検出して動力遮断+ETO 状態
- `.edm_mon` / `.hwtoin_mon` / `.eto_mon`
- `.pending_alarm` — `None` / `"circuit"`(53h) / `"detected"`(68h)
- `.clear_eto()` — ETO-CLR。両方 ON のときだけ成功

### なぜこれをやるか

HWTO は「配線 → 入力 → 内部状態 → 出力とアラーム」という純粋な組合せ＋時間の論理で、
CAN とは無関係。driver 層に閉じて置けばテストが容易で、Web からもシナリオからも同じ
モデルを使える。

- [ ] Step 1: 失敗するテストを書く（実測した仕様表をそのままテストにする）
  - `両方 ON では power_cut も eto_active も False`
  - `HWTO1 だけ OFF → power_cut True / eto_active False / hwtoin_mon True / edm_mon False`
  - `両方 OFF → eto_active True / edm_mon True / eto_mon True`
  - `1ms のオフショットパルスでは power_cut にならない`（OFF が 1ms 以下は無視）
  - `dual_mismatch_delay_ms=0（無効）なら片系 OFF が続いても 53h は出ない`
  - `dual_mismatch_delay_ms=50 で片系 OFF が 50ms 続くと 53h が出る`
  - `dual_mismatch_delay_ms=50 でも 50ms 以内にもう片方も OFF なら 53h は出ない`
  - `alarm_on_off_input=True なら OFF で 68h が出る / False なら出ない`
  - `clear_eto() は両方 ON のときだけ eto_active を落とす`
- [ ] Step 2-4: 実装してテストを通す
- [ ] Step 5: コミット `feat: HWTO (動力遮断機能) のモデルを driver 層に追加する`
