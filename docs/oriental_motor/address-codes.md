# アドレスコード（NET-ID）と実機 mxex の実測値

出典: HP-5141J「7 アドレスコード一覧 / 13-6 動力遮断・ETO・アラーム設定」を
`pdftotext -layout` で抽出（2026-08-09 実測）。値は `scripts/mxex_dump.py` で
`docs/oriental_motor/日本アクセス_右モーター.mxex` / `_左モーター.mxex` から読み出したもの。

全パラメータの表を起こすのは P5 の作業。ここは P3.5 で必要になった
動力遮断・ETO まわりだけを確定させた記録。

## 動力遮断・ETO 設定

| NET-ID | Modbus 上位/下位 | パラメータ名 | 設定範囲 | 初期値 | 右モーター | 左モーター |
|---|---|---|---|---|---|---|
| 400 (0190h) | 800/801 (0320h/0321h) | HWTO 入力 OFF 時アラーム発生 | 0:無効 / 1:有効 | 0 | **0** | **0** |
| 401 (0191h) | 802/803 (0322h/0323h) | HWTO-2 重系異常検出遅延時間 | 0-10:無効 / 11-100 ms | 0 | **0** | **0** |
| 408 (0198h) | 816/817 (0330h/0331h) | ETO 解除無効時間 | 0-100 ms | 0 | **0** | **0** |
| 409 (0199h) | 818/819 (0332h/0333h) | ETO 解除動作（ETO-CLR 入力） | 1:ON エッジ / 2:ON レベル | 1 | **1** | **1** |
| 410 (019Ah) | 820/821 (0334h/0335h) | ETO 解除動作（ALM-RST 入力） | 0:解除無効 / 1:ON エッジ | 0 | **0** | **0** |
| 411 (019Bh) | 822/823 (0336h/0337h) | ETO 解除動作（S-ON 入力） | 0:解除無効 / 1:ON エッジ | 1 | **1** | **1** |

**実測の結論: 実機 2 台とも、動力遮断・ETO 関連のパラメータは全て初期値のまま。**

- したがって「HWTO1 だけを安全リレーで切る」片系配線でも、
  HWTO 入力回路異常アラーム（53h）も HWTO 入力検出アラーム（68h）も発生しない。
  実機が問題なく運用できている理由がこれで説明できる。
- 事前の想定（mxex で HWTO のオプションを変更している）は、この 6 個については
  当てはまらなかった。変更されているのは別のパラメータの可能性がある。
  右モーターと左モーターで値が違う netid は **17152（右 2 / 左 1）だけ** で、
  これは 1 台ずつ別 ID を振る類のもの（ノード ID 等）と見られる。特定は P5 の
  アドレスコード表全抽出に回す。

## これらは CANopen からは触れない

`1400h` 等の通信パラメータと違い、上表のパラメータは **CANopen の EDS に存在しない**
（`BLVD-KRD_CANopen_V400.eds` に 4190h/4191h は無い）。MEXE02（PC Link / Modbus）
専用であり、SDO では読み書きできない。omsim では `HwtoModel` のコンストラクタ引数
（`alarm_on_off_input` / `dual_mismatch_delay_ms`）として持つ。

例外は `40D0h Clear ETO` で、これは EDS にあり SDO から実行できる（P3.5 で実装済み）。
